# Формат аннотаций

Актуальный формат применяется ко всем 24 аннотациям D001–D024. Основная схема —
`annotation.levels.schema.json`; `annotation.schema.json` содержит совместимую копию.
Новые аннотации начинают со статуса `pending`. Все существующие 24 аннотации получили
`verified` по прямому указанию автора от 27.11.2026; история — `human_review_log.json`.

## Поля

- `dialogue_id` — ID диалога.
- `human_assessment` — принятая автором оценка GUILT: А/Б/В = 1, К = 0.
- `guilt.value` — исходное решение модели; `model_correct` — его совпадение с человеческой меткой.
- `guilt.evidence` — точные цитаты A1–A6 и обоснования.
- `nat.score`, `nat.reason`, `nat.issues` — исходная оценка NAT модели и её объяснение.
- `occurrences` — реализации G01–G15: ID, код, уровень, реплики, точные цитаты и функция.
- `review_status` — статус проверки человеком; он не означает, что модель приняла верное решение.

Оценки NAT человека хранятся отдельно: `../05_annotations/human_nat.csv`.
Они не заменяют машинный `nat.score`. Принятые человеком метки GUILT заданы по группе;
они не документируют независимое слепое решение о каждом спорном фрагменте.

## Уровни и единицы

| Коды | Уровень |
|---|---|
| G01–G04 | лексический |
| G05 | словообразовательный |
| G06 | морфологический |
| G07–G09 | лексико-грамматический |
| G10–G13 | синтаксический |
| G14 | семантико-прагматический |
| G15 | текстово-дискурсивный |

Сортировка: уровень, G-код, реплика, позиция цитаты; затем ID E001, E002 и далее.
Изменения идентификаторов при упорядочивании записаны в `occurrence_id_changes.csv`.
Лексические, синтаксические, прагматические и дискурсивные реализации могут быть вложенными,
если функция каждого кода обоснована. Вхождение формы само по себе не является реализацией.
Повторы одной формы внутри одного приёма не создают дополнительные единицы.
G14 учитывает отдельный речевой акт, G15 — одну последовательность минимум из двух ответов.
Для G15 требуется по одной точной цитате из каждой реплики в том же порядке.
При `guilt.value = 0` evidence и occurrences пусты.

Полная инструкция: `annotation_prompt_levels.md`. Историческое ограничение тремя ведущими
средствами не действует в текущем протоколе. Различия прежних подходов к отбору описаны
в `data_gaps.md`; организационная проверка не подменяет содержательную переразметку.
