# Формат аннотации

Формальная схема: `annotation.schema.json`; пустой пример: `annotation.empty.example.json` (он не является результатом исследования). Одну аннотацию сохраняют в `05_annotations/DXXX.json`. Измените ID на нужный и заполните структуру после утверждения методики. `pending` — черновая оценка; `verified` — автор проверил содержание, цитаты и единицы анализа. Для verified обязательны GUILT 0/1, NAT 1–5 и непустое объяснение NAT; GUILT 1 требует подтверждающих фрагментов.

Каждый элемент `evidence` и `problem_fragments` имеет `turn` (A1–A6), `quote` (точная подстрока этой реплики) и `explanation` (обоснование). Каждый элемент `occurrences` содержит `code`, `evidence` (один или несколько таких фрагментов) и общее `explanation`. G15 с несколькими репликами — один объект `occurrences`, содержащий несколько свидетельств. G14 — один объект на отдельный речевой акт. Пустые списки допустимы при отсутствии соответствующих фрагментов. Непроверенные значения в пустом шаблоне — `null`, а не нули.

Скрипт проверяет схему, ID, цитаты, точные дубли реализаций и наличие обязательных оценок. Он не способен установить правильность интерпретации, отделить два похожих речевых акта, распознать пересекающиеся дубли G15 или удостовериться в качестве экспертного решения. Вручную проверяйте эти обстоятельства перед установкой `verified`.
